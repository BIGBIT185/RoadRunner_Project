# 可见性清理与高度上界开关（2026-10-23）

用户要求将可见性清理、高度上界更新作为可选功能。沿用唯一参数文件里的`enable_visibility_cleanup`和`enable_upper_bound`，默认都为true，重启算法生效，不增加配置文件或运行模式。两者均依赖`enable_elevation_map_lifecycle: true`。

现有内核已经区分两个功能，但外层在两者关闭时仍然采样射线并调用无证据的更新。修改新工程的`geometry/gpu_rolling_elevation.py`：只在任一功能开启时生成射线证据，并跳过两者都关闭时的可见性更新；高斯融合后的真实观测有效度刷新继续保留。其他生命周期功能保持各自开关和原行为。

实施顺序：

- [x] 先补测试，验证同时关闭时不采样射线、不执行无证据的可见性更新，真实高程仍被融合且有效度为1。
- [x] 验证四种开关组合的实际高程清理、上界状态和诊断；仅修改缺失的跳过逻辑。
- [x] 运行核心回归，更新配置注释、README、来源差异和AI交接。默认配置与当前运行状态保持开启，不自动切换用户正在使用的算法。

验收不以固定帧率为标准；本次不承诺关闭后达到10Hz，也不将未知区域填为可通行。

验证结果：新增6例，修改前3失败/3通过，失败覆盖关闭后仍采样、仍执行空更新以及射线诊断不为0；修改后核心回归649通过、1跳过。另在真实CuPy/CUDA上以合成平地点云检查四种组合，均通过；同时关闭时射线数0，225格真实高程有效、有效度1。

证据：`reports/visibility-options-before.log`、`reports/visibility-options-tests.log`及`reports/visibility-options-gpu.json`。几何环境跳过项仍是缺少Transformers的可选处理器测试，初次迁移时已在独立语义环境执行该用例通过。本次没有重放GOOSE或对新开关做实包速度基准。

随后用户询问实际帧率，已补做同段GOOSE回放对比：两项开启2.35Hz，同时关闭6.67Hz，语义均约2Hz。详见[实包帧率对比](../reports/可见性开关帧率对比.md)。测试后恢复默认两项开启，持久YAML未改。
