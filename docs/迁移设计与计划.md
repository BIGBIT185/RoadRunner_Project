# RoadRunner 建图核心工程整理（2026-10-23）

用户授权将现有 RoadRunner 中的在线建图核心复制整理到本目录；原工作区保留。验收追加要求：使用本机 GOOSE rosbag 测试。

## 设计

采用一个 catkin 工作区、一个 ROS 包 `roadrunner_mapping`、一份 `config/mapping.yaml` 和一个 `launch/mapping.launch`。仅迁移两条在线流水线及其实际传递依赖：GPU 高斯滚动高程/生命周期/几何风险，以及 EoMT 图像语义/点云投影/增量语义/概率融合。整理模块名和导入路径，不重写数学算法；不迁移导航、仿真、数据集下载/生成或其他传感器配置。

输入为 `sensor_msgs/PointCloud2`、`sensor_msgs/Image`、`sensor_msgs/CameraInfo` 和 TF。默认沿用 GOOSE 测试包的接口和标定，统一从参数文件调整；本工程不提供 SLAM/定位，也不伪造运动 TF。保留原始 XYZ/intensity 点云契约，文档明确字段要求。

图像必须已校正，编码 rgb8/bgr8；CameraInfo 的 P/ROI/binning 与该图像匹配。TF 链须在输入时间可查询 world↔base↔lidar↔camera。输出高程为当前 base_link 车体系米制 Z，概率为 1-risk，未知格为 NaN。非对称栅格测试同时检查列主序与 (+x,+y)/(-x,-y) 的格位置；保持原 GridMap 转换，不额外套用 OccupancyGrid 的翻转。

建图节点发布原概率 GridMap、CVaR 概率 GridMap 和米制高程 Image。为 RViz 在真实地形高度上着色，在同次发布中将米制 `elevation` 层加入两种 GridMap；无效高程保持 NaN。RViz 配置明确指定高度层为 elevation、颜色层为 final_probability，避免把概率画成高度。默认地图参数保持来源 GOOSE 配置，不引入 BeamNG 先验或坡度包装。

默认保留 EoMT/RUGD24 语义后端，复制本机可用模型文件与 SHA256 清单到 `models/`，权重不进入 Git。语义与几何使用各自的 Python 环境，通过本工程生成的自定义消息通信。只共用安装环境，运行源码、生成消息和模型均来自新工程，不通过旧工作区或 `/tmp` 部署副本导入。

单份 YAML 同时加载为建图与语义节点私有参数，公共参数（输入图像、设备、类别、模型路径）只定义一次；未被某节点使用的键不影响其行为。时钟与是否开启语义通过少量 launch 参数控制。提供构建、运行、回放和检查脚本；按功能使用独立 tmux 会话。

## 实施与验收计划

1. 记录原库 HEAD、工作区差异与源文件哈希；计算在线节点的 Python 依赖闭包，复制到 `src/roadrunner_mapping/`。目录分为 `geometry/`、`online/`、`sensors/`、`semantics/`；只做可追踪的名称替换，保留算法来源清单。
2. 新建 package/CMake/setup、自定义消息、单份 YAML、统一 launch 和 RViz 配置；保留高程及普通/CVaR 概率输出。仅修改运行路径、输出整合等工程接口。
3. 复制语义模型、依赖版本清单，提供构建和运行脚本、README、输入/输出契约；不复制原数据包和旧构建产物。
4. 迁移与当前核心相关的数值/状态回归。在新输出整合前先添加实际 GridMap 测试，验证高程单位、数组布局、无效格和概率范围；完成 catkin 构建和导入检查。
5. 独立 ROS master、独立功能 tmux 会话回放 GOOSE。检查输入图像/点云/CameraInfo/TF、模型就绪、语义预测及语义融合计数、有效高程与概率、地图几何尺寸、RViz 插件和显示。
6. 保存测试报告、迁移清单与来源差异，确认运行时未导入旧 RoadRunner 源码；更新 HOUND AI 交接的新工程入口。明确区分离线检查与实际 bag 验收。

## 取舍与边界

直接复制整个仓库会带入无关入口；彻底重写核心会增加算法回归风险，因此采用依赖闭包迁移并保留现有数值实现。先沿用 GOOSE 输入契约，以真实 bag 验证；更换硬件时只改同一份配置和外部标定/TF，不增加实车/仿真/bag 多套配置。

本地权重约 1.2 GiB；不复制整套训练仓库。Python/CUDA/ROS 环境为安装依赖，默认复用已有容器，README 列出可复现版本和必要 ROS 包。没有真实传感器或仿真闭环验收，本次不控制车辆。
